7.5 Backend order-placement requirements

Implement a server-side order-creation operation, for example:

POST /api/orders

The exact route may follow your existing Next.js route-handler or backend architecture.

Request handling

The backend must:

Authenticate the request using the existing session system.

Validate the request schema and reject malformed input.

Read the product IDs and quantities from the request.

Fetch current product prices and stock from the database.

Reject missing, inactive, unavailable, or out-of-stock products.

Validate quantities and applicable purchase limits.

Verify ownership of the selected address.

Recalculate subtotal, shipping, taxes, discounts, and total on the server.

Apply the chosen payment workflow.

Create the order and its item snapshots in a database transaction.

Reserve or decrement inventory consistently, preventing overselling.

Return the created order's public identifier and current status.

Never accept a browser-submitted total as the amount to charge or store without independently recalculating it.

Duplicate submission protection

Disable the Place Order button while a request is in progress.

Use an idempotency key or equivalent request-deduplication strategy.

A repeated request with the same key must not create duplicate orders.

If the network fails after submission, provide a safe way to recover the existing result rather than blindly placing another order.
